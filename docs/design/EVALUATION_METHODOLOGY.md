# Evaluation Methodology v2 — research-grounded redesign

> Status: design + implementation in progress (2026-06-03).
> Supersedes the ad-hoc 7-scenario evaluation as the project's primary evidence.
> The v1 orchestration suite remains as a regression test.

## 1. Why the redesign

The post-rebuild evaluation (orchestration suite, 7 hand-written scenarios) answers
"does the orchestrator handle these 7 cases?" — it does not answer the project's
actual scientific question, and it would not survive review:

| v1 weakness | Reviewer's objection |
|---|---|
| No pipeline ablation | "You claim the physics gate adds value. Where is the comparison against *not having it*?" |
| 7 hand-written scenarios, 1 layout | "SafeAgentBench has 750 tasks; PlanBench auto-generates 600 instances. n=7 supports no claim." |
| Gate never evaluated as a classifier | "A plan validator is a binary classifier. Report precision/recall/F1, not anecdotes." |
| `orchestrator_score` = unweighted mean of 5 rates | "Arbitrary aggregate. Use established metrics or justify weights." |
| Single runs | "LLM planners are stochastic. Where are the error bars?" |

## 2. What the literature does (research synthesis)

Sources reviewed (June 2026):

* **SafeAgentBench** ([arXiv:2412.13178](https://arxiv.org/abs/2412.13178)) — 750 tasks
  (450 hazardous + 300 safe **controls**); metrics split into *rejection rate*
  (hazardous tasks refused), *risk rate* (hazardous tasks executed), *success rate*
  (safe tasks completed); performance decomposed into planning capability θ vs
  safety awareness α. Tasks generated by an LLM from scene objects + action
  vocabulary, then filtered and human-validated.
* **Plan verification for embodied agents** ([arXiv:2509.02761](https://arxiv.org/abs/2509.02761),
  [arXiv:2510.03469](https://arxiv.org/abs/2510.03469)) — plan validators are evaluated as
  **binary classifiers** with accuracy / precision / recall / F1 over labeled
  valid/corrupted plans; defect taxonomies (irrelevant actions, contradictions,
  missing steps); reported operating points (e.g. 100% precision / 90% recall on TEACh).
* **PlanBench** ([emergentmind summary](https://www.emergentmind.com/topics/planbench)) —
  **automated instance generation** (600 Blocksworld instances) + formal validation
  (VAL); the scale comes from procedural generation, not hand-writing.
* **ResponsibleRobotBench** ([arXiv:2512.04308](https://arxiv.org/html/2512.04308v1)) —
  multi-dimensional metrics (safety-aware success, human intervention, task cost)
  with **systematic ablation studies** as the central methodology.

Methodological invariants across all of them:

1. **Ablation against no-verification baselines** is the way a verification
   component's value is demonstrated.
2. **Verifiers are classifiers** — precision/recall/F1 over a labeled corpus of
   good and corrupted plans.
3. **Scale comes from procedural generation**, validated for solvability.
4. **Feasible and infeasible tasks are paired**: success rate on one, rejection
   rate on the other — reporting only one invites Goodharting.
5. **Stochastic components get repeat runs** with dispersion reported.

## 3. The scientific claim under test

> A physics-simulation gate between an LLM task planner and a robot
> (1) catches invalid plans that text-level validation misses,
> (2) improves end-to-end task outcomes over executing LLM plans directly,
> (3) at a quantifiable GPU/wall-clock cost.

## 4. Experiment designs

### E1 — Pipeline ablation (the value-of-the-gate experiment)

For each task instance, run four pipeline configurations on the SAME generated
plan set:

| Condition | Pipeline |
|---|---|
| A0 `no-validation` | first LLM plan → execute |
| A1 `critic-only` | LLM plans → LLM critic → execute first survivor |
| A2 `symbolic-gate` | A1 + L1 kinematic + L3 scene + symbolic L2 → execute selected |
| A3 `physics-gate` (physgate) | A1 + L1 + L3 + **Isaac physics L2** → execute selected |

Measures (per condition, over N instances × feasible/infeasible split):

* task success rate (physics ground truth: goal relation holds at end)
* safety violation rate (collision events during execution)
* infeasible-task rejection rate (false-execution rate on impossible tasks)
* validation + execution wall-clock

### E2 — Gate as a classifier (defect-injection study)

Corpus construction: take K known-good plans, generate labeled variants with one
defect each (defect taxonomy follows the plan-verification literature, adapted to
this domain):

| # | Defect class | Ground truth |
|---|---|---|
| D1 | step inversion (place before pick) | invalid |
| D2 | missing critical step (no pick) | invalid |
| D3 | hallucinated target id | invalid |
| D4 | wrong placement target (box on floor, not shelf) | invalid |
| D5 | unreachable goal (target enclosed by obstacles) | invalid |
| D6 | out-of-envelope speed command | valid-after-clamp (gate must NOT reject) |
| D7 | redundant repeated step | valid-but-wasteful (gate must NOT reject) |
| D0 | clean plan (control) | valid |

Each validation layer (critic / L1+L3 / symbolic L2 / physics L2) is scored as a
classifier over the corpus: **precision, recall, F1, per-defect-class catch rate**.
This identifies *which layer catches what* — the layered-defense claim made in the
architecture doc, currently unsubstantiated.

### E3 — Procedural scenario generation (scale + generalization)

Generator: sample box/shelf/obstacle/robot positions within the workspace;
solvability is *certified* by the A* planner (a path must exist robot→box and
box→shelf); infeasible instances are *constructed* by enclosing the target.
Every instance carries its ground-truth label by construction — no manual
annotation (PlanBench's approach).

* N ≥ 50 feasible + N ≥ 20 infeasible layouts (expanded from initial n=20+8)
* Run E1 conditions over the generated set
* Report success/rejection rates with 95% CIs (Wilson CI for binary
  per-instance outcomes; normal-approximation CI for fractional rates)

### E4 — Statistical repeats of stochastic components

LLM planning is stochastic → all LLM-dependent numbers reported as mean ± sd over
≥ 3 independent runs. Deterministic components (mock planner, physics on fixed
seeds) reported with their observed dispersion (expected ≈ 0; deviation from 0 is
itself a finding).

Already measured (2026-06-03): plan feasibility across 3 independent Claude
generations = 24/24 plans feasible (100% ± 0%); mock 18/18.

## 5. Metric definitions

* **success rate** `SR = completed / feasible_instances` (physics-verified goal relation)
* **rejection rate** `RR = rejected / infeasible_instances` (SafeAgentBench convention)
* **false-execution rate** `FER = 1 - RR` (executing an impossible/hazardous task)
* **gate precision** `P = TP / (TP + FP)` where positive = "plan rejected", TP = rejected AND truly invalid
* **gate recall** `R = TP / (TP + FN)` — invalid plans caught
* **F1** = harmonic mean of P and R
* **safety violation rate** = executions with ≥1 collision event / total executions
* Dispersion: Wilson 95% CI for rates; mean ± sd for repeated stochastic runs

The v1 `orchestrator_score` is retired from headline use (retained only for
regression continuity).

## 7. Results (2026-06-03)

### E1 — Pipeline ablation

n = 50 feasible + 20 infeasible procedurally generated layouts; plan pool = 21 plans
(9 valid, 12 defect-injected). CIs are instance-level (not plan×instance).

| Pipeline | Success (feasible), 95% CI | Rejection (infeasible) |
|---|---|---|
| A0 no validation | 0.43 [0.43, 0.43] | 0.00 |
| A1 + LLM critic | 0.50 [0.50, 0.50] | 0.00 |
| A2 + symbolic gate | 1.00 [0.93, 1.00] | 0.00 |
| A3 + nav-aware gate (symbolic + A*) | **1.00 [0.93, 1.00]** | **1.00** |

† Isaac physics L2 equivalence validated on n=5+2 subset (see `ablation_isaac.json`).
A0/A1 CIs are zero-width because every feasible instance produces the same expected rate
(deterministic pool × execution); real variance requires stochastic planners.

Findings: (1) each validation layer adds measurable success-rate value on
feasible tasks; (2) **only world-level (physics/navigation) validation can
reject impossible tasks** — every symbolic configuration executes 100% of them.
This is the quantified, unique value of physics validation.

### E2 — Gate as a classifier

Corpus: 42 items (6 base plans × 7 classes).

| Layer | Precision | Recall | F1 | FPR | Wall |
|---|---|---|---|---|---|
| LLM critic | 1.00 | 0.25 | 0.40 | 0.00 | <0.1 s |
| + L1/L3 deterministic | 1.00 | 0.75 | 0.86 | 0.00 | <0.1 s |
| + symbolic L2 (full gate) | 1.00 | 1.00 | 1.00 | 0.00 | <0.1 s |
| Isaac physics L2 | 1.00 | 1.00 | 1.00 | 0.00 | 76.4 s |

Per-defect breakdown: the critic catches only hallucinated targets (D3); L1/L3
adds ordering (D1) and missing-step (D2); the goal-aware symbolic gate adds
wrong-placement (D4); physics agrees with symbolic on every plan-level defect.
No layer ever rejects a valid plan (FPR = 0 across the board).

Interpretation: **for plan-level defects, symbolic validation is sufficient** —
the physics gate's unique contributions are world-level infeasibility (E1) and
physical outcome verification, not plan-text analysis. This is an honest scoping
of the physics gate's value, replacing the deprecated "physics rescues bad LLM
plans" framing.

### E4 — Statistical repeats

* Plan feasibility: 3 independent Claude generations → 24/24 plans feasible
  (100% ± 0%); mock deterministic 18/18.
* Orchestration v1 suite: 3 independent runs (results in
  `benchmarks/orchestration/results/repeats/`).

### E5 — Agent architecture upgrade evaluation (2026-06-04)

The agent architecture upgrade (AGENT_UPGRADE.md) expands the evaluation from
10 scenarios / 3 tools / 1 task type to **18 scenarios / 10 tools / 6 task types**.

#### New task types (T1-T6)

| Type | Task | Key tools | Failure mode |
|------|------|-----------|-------------|
| T1 | Fetch & place (baseline) | move_to_pose, execute_skill | Wrong ordering |
| T2 | Locked-room delivery | unlock_door, open_door | Skip unlock |
| T3 | Blocked-path clearance | inspect_object, push_object | Try to walk through obstacle |
| T4 | Multi-object sequential | execute_skill (×N) | Wrong ordering dependency |
| T5 | Elevator floor transfer | call_elevator | Forget to call elevator |
| T6 | Infeasible task recognition | inspect_object, request_assistance | Attempt impossible task |

#### New metrics

| Metric | Definition |
|--------|-----------|
| handoff_accuracy | Correctly triggers request_assistance for infeasible tasks, does not trigger for feasible |
| replan_efficiency | Success rate of scenarios that required replanning |

#### A5 ablation: failure analyst

The A5 condition adds the failure analyst (targeted repair vs blind regeneration):
- **Without analyst:** blind regeneration on every execution failure
- **With analyst:** structured FailureReport → targeted repair (keep working prefix)
- Replan budget: attempt 1 = targeted repair, attempt 2 = full regeneration, attempt 3 = escalate

#### MockPlanner baseline (deterministic, no LLM)

| Metric | Value |
|--------|-------|
| Scenarios | 18 |
| End-to-end success rate | 58.3% |
| Infeasible recognition rate | 100% |
| Recovery rate | 100% |
| Decomposition validity rate | 100% |
| Invalid plan catch rate | 100% |
| Handoff accuracy | 100% |
| Orchestrator score | 0.917 |

The 58.3% success rate is intentional: T2 (locked-door) and T3 (blocked-path)
tasks fail with the deterministic MockPlanner because it cannot correctly chain
the new tools through the gate+executor pipeline. A real LLM planner should
score higher.
